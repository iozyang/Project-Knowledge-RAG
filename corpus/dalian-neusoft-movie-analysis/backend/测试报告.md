## 一、测试概述

### 1.1 项目简介

MovieAnalysisAPI 是一个基于 Spring Boot + MyBatis-Plus + MySQL 的电影统计分析后端服务，围绕豆瓣电影统计数据对外提供查询接口，主要涵盖年度评分 Top20 电影、类型分布、地区分布、语言分布、演员 Top50、评分区间等统计维度。

### 1.2 测试目的

- 验证各统计实体（Entity）字段与数据库表/列的映射关系正确；
- 验证持久层（Mapper）分页与条件查询逻辑正确；
- 验证业务层（Service）查询语义、参数校验与边界处理正确；
- 验证接口层（Controller）与全局异常处理的响应行为正确；
- 保证各层代码在回归时功能稳定、无失败用例。

### 1.3 测试范围

| 分层 | 测试内容 |
| --- | --- |
| Entity | 字段映射、getter/setter、equals/hashCode、toString、注解约束 |
| Mapper | 分页查询、条件查询、全量查询与数据合法性校验 |
| Service | 业务查询、分页、参数校验、去重/冲突处理 |
| Controller | 接口请求响应、参数校验、全局异常处理 |
| 应用 | Spring 上下文加载 |

### 1.5 测试策略

- **集成测试**：Entity/Mapper/Service/Controller 层普遍采用 `@SpringBootTest`，连接真实数据库，验证真实 SQL 与数据。
- **单元测试（Mock）**：`*QueryTest` 系列通过 Mockito `mock` + `ReflectionTestUtils` 注入 `baseMapper`，对查询构造逻辑进行隔离测试，不依赖数据库。
- **断言完整性**：结合 `assertEquals`、`assertNotNull`、`assertThrows`、`Assumptions.assumeFalse` 等覆盖正常与异常路径。

**主要测试内容**

1. **字段映射（`@TableName` / `@TableField`）**：校验实体类注解指向正确的数据库表名与列名，例如 `StatYearTop20Movie` 映射到 `stat_year_top20_movie`，`movieId`→`MOVIE_ID`、`name`→`NAME`、`doubanScore`→`DOUBAN_SCORE`、`doubanVotes`→`DOUBAN_VOTES`。

3. **字段数量校验**：实体声明字段数量与数据库表结构保持一致（如 `StatYearTop20Movie` 为 5 个字段）。
4. **主键约束策略（`StatisticsEntityMappingTest`）**：
   - 使用 `TableInfoHelper` 校验多行实体（`StatYearRegionCount`、`StatRegionYearAvgScore`、`StatYearTop20Movie`）**不以年份作为唯一 ID**，且不生成 `updateById`/`deleteById` 语句；

## 四、测试总结

### 4.1 结论

本次测试覆盖了 Entity、Mapper、Service、Controller 四个分层，累计 **57 个测试类、381 个测试用例**，运行结果为 **全部通过（0 失败、0 错误、0 跳过），通过率 100%，BUILD SUCCESS**。测试结果说明当前代码在各层的字段映射、查询逻辑、参数校验与接口响应方面均符合预期。

### 4.2 质量情况

- **映射正确性**：实体注解与 MyBatis-Plus 元数据校验通过，主键策略（多行实体无唯一 ID、导入型业务键为 `IdType.INPUT`）得到了有效验证。
- **查询正确性**：分页、条件、区间查询以及去重/冲突处理逻辑均通过验证。
- **健壮性**：非法参数、空数据、越界分页等异常路径均有对应断言覆盖，避免脏数据与静默失败。
- **测试隔离性**：查询构造类测试采用 Mockito 单元测试，不依赖数据库，执行快速稳定。

### 4.3 改进建议

1. 部分集成测试依赖真实 MySQL，建议引入 Testcontainers 或 H2 内存库，提升 CI 环境下的可移植性与稳定性。
2. 可补充 Service 层对写操作（若有导入/更新统计逻辑）以及并发场景的测试。
3. 建议在 CI 中接入 JaCoCo 覆盖率统计，量化行/分支覆盖率并设置阈值门禁。
4. 集成测试中数据库返回的明细日志（`StdOutImpl`）较为冗长，可在测试环境降低日志级别以精简输出。
