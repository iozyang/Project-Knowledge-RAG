# 数据分析结果结构说明

> 本文档依据 `MovieAnalysis.py`（PySpark 电影分析脚本）逐功能整理，用于在 **Sqoop 导出到 MySQL 之前** 完成两件事：
> 1. 依据结果结构在 MySQL 中建表；
> 2. 依据「HDFS 输出子路径」「字段分隔符」等信息编写 Sqoop 导出命令。

---

## 0. 通用说明（务必先读）

### 0.1 结果落盘通用规则

所有统计结果都由 `write_result(df, name)` 统一写出，规则如下：

| 项目 | 说明 |
| --- | --- |
| HDFS 根目录 | `/movies/analysis_results` |
| 每项结果子路径 | `/movies/analysis_results/<name>/`，目录下是 `part-00000` 等分片文件 |
| 文件格式 | CSV，**无表头**（`header=false`） |
| 字段分隔符 | `,`（`sep=","`，即 `CSV_SEP`） |
| 转义符 | `\`（`escape="\\"`） |
| 覆盖策略 | `mode("overwrite")`，重跑会覆盖旧结果 |

> 关键点：**写出的 CSV 不带表头**。因此 Sqoop 按列顺序导入时，MySQL 表的**列顺序必须与本文档给出的列顺序完全一致**。

### 0.2 数据类型映射（Spark → MySQL）

统计结果中出现的 Spark 类型与 MySQL 建表类型的建议对应关系：

| Spark 类型 | 含义 | 建议 MySQL 类型 |
| --- | --- | --- |
| `int` / `long`（`count` 结果） | 整数（计数） | `INT` 或 `BIGINT` |
| `int`（`cast("int")`） | 年份 | `INT` 或 `SMALLINT` |
| `double`（`avg` 结果） | 浮点（平均值） | `DOUBLE` 或 `DECIMAL(5,2)` |
| `string` | 文本（地区名/语言/电影名等） | `VARCHAR(n)` |
| `string`（`DOUBAN_VOTES`，未 cast） | 投票数（文本） | `VARCHAR(n)`，若需数值排序再转 `BIGINT` |

> 说明：`avg` 等聚合结果在 Spark 中默认为 `double`；`count` 结果为 `bigint`。建表时可适当收窄为 `INT` / `DECIMAL`。

## 附录 B：Sqoop 导出命令编写要点

> 建库建表请先执行 `movie_stat_db.sql`（本文档不再包含建表代码）。
> 下表给出 HDFS 子路径 → MySQL 表名的对应关系，用于编写 Sqoop 命令。

以「功能 4 不同地区电影数量」为例，Sqoop 导出：

```bash
# Sqoop 导出：HDFS 目录 -> MySQL 表
# 目标表 stat_region_count 由 movie_stat_db.sql 创建，
# 列顺序为 region_name, movie_cnt（与结果结构一致）
sqoop export \
  --connect "jdbc:mysql://<host>:3306/movie_stat_db" \
  --username <user> --password <pwd> \
  --table stat_region_count \
  --export-dir /movies/analysis_results/stat_region_count \
  --fields-terminated-by ',' \
  --lines-terminated-by '\n' \
  --input-null-string '\\N' --input-null-non-string '\\N'
```

要点：
1. `--export-dir` 填「HDFS 输出子路径」列对应的目录（见附录 A）；
2. `--fields-terminated-by ','` 与脚本 `CSV_SEP = ","` 保持一致；
3. 结果 CSV **无表头**，MySQL 表列数、列顺序须与本文档「结果数据结构」一致；
4. 每项统计对应一张独立的 MySQL 表，**表名与 HDFS 子路径同名**（见附录 A）；
5. 库名统一为 `movie_stat_db`。
